# OblivionDoc для Windows

Автономное приложение электронного архива на основе Python-кода, предоставленного владельцем проекта. Предыдущий браузерный прототип заменён оконным приложением.

## Скачать и запустить

Готовый файл после успешной сборки: [OblivionDoc.exe](https://github.com/Saertuu/OblivionDoc/raw/refs/heads/windows-build/OblivionDoc.exe).

Windows 10/11, 64 бита. Скачайте файл и откройте двойным щелчком. Python, браузер, PostgreSQL, установка пакетов и интернет для работы не требуются.

При первом запуске зарегистрируйтесь с почтой и паролем. Почта используется как логин; подтверждение почты не выполняется. Новый аккаунт получает пустой архив. Следующие запуски открывают экран входа: данные аккаунтов и документы сохраняются, пароль проверяется по хешу scrypt.

## Возможности

- Раздельные аккаунты с проверкой пароля и уникальности почты.
- Загрузка PDF, DOC/DOCX, TXT, PNG, JPG/JPEG до 10 МБ.
- Реестр, поиск, редактирование, скачивание, открытие через программу Windows и удаление с подтверждением.
- Архивирование или удаление по выбранному сроку. Сроки проверяются раз в минуту, пока приложение открыто. При следующем запуске обрабатываются пропущенные сроки. Удаление по сроку необратимо и требует явного выбора этого правила в карточке.
- Отдельный журнал операций каждого аккаунта.
- Имя, фамилия и настройки организации.
- Экспорт документов и журнала в XLSX.

## Где лежат данные

`%LOCALAPPDATA%\OblivionDoc\`

База `obliviondoc.db`, папки `uploads` и `archive`, настройки интерфейса и журналы. Данные не лежат внутри `.exe` и не пропадают при его обновлении или перемещении. Они не передаются на сайт и не синхронизируются между компьютерами. Старые браузерные демо-профили в приложение автоматически не переносятся.

Для резервной копии закройте приложение и скопируйте всю папку данных. Сохраните пароль: отправка писем восстановления в автономной сборке не настроена. Пользователь Windows с доступом к этой папке имеет доступ к файлам базы; это не зашифрованное хранилище.

## Исходники и проверка

Предоставленные файлы имели несоответствующие содержимому имена. Восстановлены `backend/main.py`, `models.py`, `schemas.py`, `xlsx_export.py`; база адаптирована для постоянного локального хранения. HTML-интерфейса среди вложений не было; добавлен нативный интерфейс Tkinter. Исходный текст описания сохранён в `docs/UPLOADED_README.md` для справки.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python obliviondoc.py
```

Локальная служба запускается только на `127.0.0.1` со случайным портом и ключом текущего процесса. Окно закрывается вместе со службой. Внешняя база и ключи почтовых сервисов для приложения не нужны.

## Собрать EXE

Активируйте окружение с Python 3.12 x64 на Windows и выполните:

```powershell
.\.venv\Scripts\Activate.ps1
.\scripts\build_windows.ps1
```

Файл появится в `dist\OblivionDoc.exe`. GitHub Actions также собирает его на Windows при отправке в `main` и проверяет уже собранный `.exe`: запуск окна, регистрацию, отказ при неверном пароле, изоляцию аккаунтов, сохранение документа после перезапуска процесса и экспорт. Только после успешных проверок бинарный файл публикуется в отдельной ветке `windows-build` с SHA-256 и отчётом `build-info.json`.
