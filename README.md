# OblivionDoc

Рабочий браузерный прототип электронного архива образовательной организации. Назначение уточнено по предоставленному паспорту проекта: единый реестр документов, поиск по реквизитам, сроки хранения, роли пользователей и история действий.

## Что работает

- Стартовый экран демо-регистрации: имя, почта и организация; повторный вход, гостевой доступ и выход без удаления документов.
- Реестр с поиском по названию, номеру, ответственному, имени файла и подразделению.
- Фильтры по категории, подразделению, статусу и сроку; сортировка и страницы результатов.
- Загрузка PDF, DOC/DOCX, XLS/XLSX, TXT, CSV, PNG, JPG и WebP; до 20 МБ на файл и 100 МБ на демо-архив.
- Карточки документов с редактированием реквизитов и заменой файла.
- Предпросмотр текста, изображений и PDF (если поддерживается браузером); скачивание исходного файла.
- Перенос в архив и возвращение в работу; подтверждаемое удаление для демо-администратора.
- Даты хранения и бессрочное хранение. Просроченные документы остаются в реестре до ручного решения.
- Журнал просмотра, скачивания, изменений, архивирования, удаления и выгрузки реестра.
- Экспорт отфильтрованного реестра в CSV, с экранированием формул электронных таблиц.
- Демо-роли: наблюдатель, архивариус, администратор. Ограниченные записи скрываются от наблюдателя в интерфейсе.
- Адаптивный интерфейс, светлая и тёмная темы, клавиатурная навигация и уменьшенное движение.

Восемь стартовых документов содержат вымышленные учебные примеры. Текст паспорта проекта, сведения об участниках команды и их профили не включены в приложение.

## Ограничения прототипа

**Это локальная демонстрация, а не защищённый многопользовательский архив.**

Карточки, файлы и журнал хранятся в IndexedDB браузера на том же адресе сайта и сохраняются при перезагрузке. Они не отправляются на сервер, не синхронизируются между устройствами и могут исчезнуть при очистке данных браузера, смене адреса сайта или вытеснении хранилища браузером. Используйте тестовые файлы; сохраняйте отдельные копии документов.

Демо-регистрация сохраняет один локальный профиль (имя, почту и организацию) в localStorage. Пароли не запрашиваются, не сохраняются и не отправляются. Почта не подтверждается; повторный вход лишь выбирает профиль этого браузера, без проверки личности. Выбор профиля/гостя запоминается в sessionStorage текущей вкладки. Гость и профиль открывают один и тот же локальный архив. Выход не удаляет профиль или файлы.

Переключатель ролей демонстрирует поведение интерфейса. Пользователь, имеющий доступ к браузеру, может менять локальные данные через инструменты разработчика. Серверная регистрация, настоящая авторизация, проверка доступа, защищённое совместное хранение, резервные копии и внешние уведомления пока не реализованы. Журнал локален и не является защищённым аудиторским следом. Приложение не заявляет соответствие нормативным требованиям к архивам или защите персональных данных.

## Запуск

Node.js >= 22.13.0 (проверено с Node.js 24).

```sh
cd /workspace/OblivionDoc
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

```sh
npm run build
npm run preview
npm run test:e2e
```

Браузерные тесты используют системный `/usr/bin/chromium`, если он есть. Иначе задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` или установите Chromium командой `npx playwright install chromium` и необходимые системные библиотеки. Тесты автоматически поднимают production-preview на порту 4173.

## Структура

- `src/archive/types.ts` — модель документа, роли и категории.
- `src/archive/database.ts` — транзакции IndexedDB, файлы, журнал и начальные примеры.
- `src/archive/format.ts` — даты, размеры и безопасный CSV.
- `src/auth/demoSession.ts` — локальный демо-профиль и выбор сессии, без настоящей аутентификации.
- `src/components/` — реестр, диалоги, карточки и разделы архива.
- `src/App.tsx` — навигация, фильтры и пользовательские действия.
- `src/tokens.css`, `src/styles.css` — темы и адаптивное оформление.
- `tests/archive.spec.ts` — сквозные проверки реальных сценариев, файлов, доступности и мобильной версии.
- `tests/auth.spec.ts` — формы демо-регистрации и входа, сохранность файлов при выходе, доступность и адаптивность.

## Публикация

Workflow `.github/workflows/pages.yml` собирает `dist` и публикует его при отправке в `main`. В GitHub Settings → Pages → Source должен быть выбран GitHub Actions. Тариф GitHub должен поддерживать Pages для видимости репозитория. Адрес публикации берётся из успешного задания deploy.

Относительная база Vite и hash-навигация позволяют обслуживать сайт из `/OblivionDoc/` без серверных rewrite-правил. Готовую папку `dist` также можно загрузить на Netlify. Смена домена создаёт другое локальное хранилище. Индексирование демо отключено.

## Следующий этап

Для пилота организации требуется сервер: аутентификация и восстановление доступа, изоляция организаций, серверные политики ролей, база реквизитов, закрытое файловое хранилище, проверка загружаемых файлов, резервное копирование и защищённый журнал. Сроки хранения должны задаваться по согласованной номенклатуре дел, а не вычисляться как универсальная правовая норма.
